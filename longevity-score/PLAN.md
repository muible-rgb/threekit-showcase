# The Long Game - Build Plan

## The one thing to protect

Scoring is cohort-relative. A 78-year-old woman can outscore a 30-year-old man,
because both are measured against their own sex + 5-year age band. Every number
the user sees is a percentile first. Raw values are secondary and always shown
next to the percentile, never instead of it.

Two denominators, never blended:

- **Longevity Score** - vs. published general-population norms. The health claim.
- **Crew rank** - vs. other people in the session. The game.

## Architecture decisions made up front

**1. Norms are data.** Every mean, SD and percentile cut-point lives in
`/data/norms/v1/<test_variant>.json`. Zero normative constants in TypeScript.
The engine takes a `NormsRegistry` as an argument - it never imports a file
itself. That is what makes it a pure, fully testable unit.

**2. The battery is versioned in the schema on day one.** `battery_versions` →
`battery_version_tests` → `test_variants` → `capacities`. A 65+ battery that
swaps wall sit for chair stand is an INSERT, not a migration. The composite
stays comparable because it is always the mean of 10 capacity percentiles.

**3. Results are immutable.** `results` rows are append-only, enforced by a
Postgres trigger, not by convention. A correction writes a new row that
supersedes the old one. Percentiles are derived and recomputed on demand, so
re-norming is a background job, not a data migration.

**4. Storage is behind a repository interface.** `DataStore` has two adapters:

- `LocalStore` - IndexedDB/localStorage, seeded with the demo dataset. Used
  automatically when Supabase env vars are absent.
- `SupabaseStore` - Postgres + RLS.

This is what makes "demo seed data renders every screen on a fresh install" and
"airplane mode loses zero results" the same mechanism instead of two. Writes
always land locally first and drain to Supabase through an outbox queue.

**5. No partial composites, anywhere.** 9 of 10 tests produces `composite:
null` and a "9/10 tests, incomplete" label. This is a product rule, not a
display rule - it is enforced in the engine so no surface can leak one.

## Phases

### Phase 0 - Scaffold
Next.js 15 App Router, TypeScript strict, Tailwind v4, Vitest. No UI.

### Phase 1 - Data model
`supabase/migrations/0001_init.sql`: tables, RLS, immutability trigger,
join-code generation.
`0002_battery_open_v1.sql`: capacities, test variants, the battery version.

**Changed during the build:** no SQL seed migration. The demo dataset lives in
the local store instead. Writing eight fake people plus `auth.users` rows into
a real Postgres with RLS is worse than it looks, and the requirement - every
screen renders with data on first run - is met by the local seed, which is what
actually runs on a fresh checkout. A Supabase install starts empty on purpose.

### Phase 2 - Norms
JSON schema + validator script. Four files sourced from published tables
(grip, push-ups, Cooper, single-leg balance). Six provisional files
(sit-rising, broad jump, dead hang, wall sit, farmer carry, 400m) generated by
a committed, parameterised script so the curve is auditable rather than
hand-waved. `TODO_RENORM.md` sets the re-fit policy.

**Provisional rule, applied consistently:** a file is `provisional: false` only
when BOTH the central tendency and the dispersion come from the cited source.
Anything where an SD was inferred is `provisional: true` with a `notes` field
saying exactly what was inferred.

### Phase 3 - Scoring engine (pure, no I/O, full unit coverage)
Layer 1 raw → Layer 2 cohort percentile → Layer 3 composite.
Ships with tests before any UI imports it.

- `normal.ts` - normal CDF + inverse, no dependency
- `cohort.ts` - age at test, 5-year band resolution
- `percentile.ts` - mean/SD path, cut-point interpolation path, direction, 1-99 clamp
- `composite.ts` - mean of 10, bands, all-or-nothing rule
- `fitness-age.ts` - median of per-test 50th-percentile age lookups
- `board.ts` - crew ranking, tie-break, most-improved
- `delta.ts` - retest deltas

### Phase 4 - Data layer + offline
`DataStore` interface, both adapters, outbox queue, sync indicator.

### Phase 5 - Screens
Home → Test mode → Score → Crew session → Methodology. Mobile-first.

### Phase 6 - Share card + public pages
`/s/[completionId]` public score page, `/share/[completionId].png` via
`next/og` at 1080x1080 and 1200x630.

### Phase 7 - PWA + polish
Manifest, service worker, install prompt, `/admin/norms`.

## Out of scope for v1

Global leaderboard, training plans, wearables, social feed, payments, native
wrapper, weighted composite, admin beyond `/admin/norms`.

## Acceptance criteria → where each is proven

| Criterion | Proven by |
|---|---|
| Both norms formats, both directions, floor/cap | `percentile.test.ts` |
| Missing tests → null composite | `composite.test.ts` |
| Band boundaries | `composite.test.ts` |
| Fitness age | `fitness-age.test.ts` |
| Tie-break, most-improved ± prior battery | `board.test.ts` |
| Full battery on a phone, score in <90s | Test mode: no blocking network call on save |
| Guests claim results by email | `participants.user_id` nullable + claim flow |
| Airplane mode loses zero results | Outbox queue, local write is the source of truth |
| Every percentile traces to a citation | `/methodology`, generated from the norms files |
| Seed data renders every screen | `LocalStore` ships pre-seeded |

## Status

All seven phases shipped. 153 unit tests, clean lint and typecheck, verified end
to end in a real browser including a complete battery run in airplane mode.

Three things found by building rather than by planning, all fixed:

1. The fitness-age curve is not monotone - grip strength peaks in the late
   twenties, so a naive scan finds two crossings and picks the wrong one. The
   lookup now reads the declining tail from the peak.
2. The service worker registered on the `load` event from inside an effect,
   which silently never fires when the effect runs after load. Invisible until
   someone is in a park with no signal.
3. The service worker ignored Next's RSC fetches, so every in-app navigation
   died offline - right at the moment someone finishes a battery and taps
   through to their score.

One thing found that is not a bug and cannot be fixed in code: fitness age
saturates at the bottom of the norms range for exactly this app's audience.
See the known limits section of README.md.
